# ADR-0011: Resumable eval collection: abandoned traces, the label join and the D1 split

- **Status:** Proposed
- **Date:** 2026-11-17
- **Issue:** #70 (part of #19). The number is the next free one; it is assigned at merge.
- **Decider:** Daniil Krizhanovskyi

## Context

D1 collection (#19) is about 14 h of serial runs on the shared kind cluster. The #14 drivers
could not resume a killed run: the run phase deleted the ledger and re-ran every plan entry.
Three facts shape a resumable run:

- **An injection id is not a trace id.** `injection_id` derives from (run, kind, query)
  (ADR-0008), so the entry that was in flight at a kill runs again with the same injection id
  under a new trace id. The spans of the killed trace are stored, partly, and carry the same
  `aegis.fault.injection.id`.
- **The split must not depend on the traces.** Design §1.6 splits calibration and test by
  source query. A split drawn after collection can be redrawn until the numbers look good.
- **A different seed is not a different query.** A D1 sample of 130 answerable CUAD questions
  shares questions with the 12 candidates of the #14 validation run, and 90 seeded runbook
  tasks have only 70 distinct (scenario, parameters) tuples, 4 of them validation's.

## Decision

1. **A trace that completed no plan entry is abandoned, and recorded in a new table.**
   `eval_exclusions` (`trace_id`, `eval_run_id`, `service`, `entry_id`, `attempt_id`,
   `planned_fault_kind`, `injection_id`, `reason`, `source`), `ReplacingMergeTree`, no TTL. It
   is never written to `eval_traces` or `injections`, and nothing is deleted from `spans`.
2. **An `eval_traces` row means a completed trace.** `record` writes one row per ledger line,
   after the run; a ledger line is appended only after the trace has ended, durably, and the
   ledger is never rewritten. A torn last line is not a line: every reader refuses it, and
   only a resume cuts it off. `record` refuses a ledger that names an abandoned trace.
3. **Ground truth is joined from `eval_traces.trace_id`, never on the injection id alone.**
   The one label read (`eval_dataset_read.sql`, `traceblame_faults.dataset`) joins `injections`
   on `(trace_id, injection_id)`. Detectors and the attributor read neither table (rule 9),
   and `eval_exclusions` joins the tables they may not name.
4. **No stored trace of a run is unaccounted for.** The check lists every trace stored under
   the run's `aegis.eval.run.id`; one that is neither in `eval_traces` nor abandoned fails the
   run, unless its marker or its start time attributes it to exactly one entry that was in
   flight, in which case it is abandoned with source `orphan_sweep`.
5. **A resume runs on the provenance of the run's first attempt** (both checkouts, image IDs,
   migrations, plan, preload, fault library, model) or not at all. There is no override; the
   remedy is a new run id.
6. **The D1 split is a committed list.** `tools/faults/plans/d1.queries.jsonl` holds every
   source query with its split side, generated by a seeded pure function before any trace
   exists and verified by the drivers at prepare/build. Half the queries per app on each side,
   and every fault kind within 2 queries of half on the test side. The grouping key is the
   CUAD question id, and for runbook tasks the (scenario, parameters) tuple.
7. **D1 excludes the validation run's candidate queries by list**, CUAD by question id and
   runbook tasks by tuple, and its runbook tasks have distinct tuples.

## Alternatives considered

- **A status column on `eval_traces` / `injections`.** Every present and future reader would
  need the filter, and one that forgets it silently adds partial traces to D1, each a second
  trace for an injection id that is already there. Rejected for the table that readers never
  join.
- **Deleting the abandoned trace's spans.** Loses the audit trail and needs a mutation on a
  table the pipeline writes. Rejected.
- **A new injection id per attempt.** Changes ADR-0008's derivation and makes the plan depend
  on the attempt. Rejected: the id stays a pure function of the plan.
- **A split rule only (seed and share in the plan file).** Deterministic, but the assignment
  is then visible only after a prepare, and a test cannot check the real D1 queries against
  validation's without the archive. Rejected for the committed list.
- **Grouping CUAD questions by contract.** Stricter than §1.6. Not done: the report states
  how many contracts have questions on both sides (17 of 62 in the committed list).

## Consequences

- One more ClickHouse table (an expand migration, no ALTER); `record` on a schema without it
  works when there is nothing abandoned and refuses before writing otherwise.
- A resumed D1 holds, per injection id, one labelled trace and possibly unlabelled partial
  ones. Anything that reads `spans` by marker alone sees both; such a read is not a label read.
- A `make kind-deploy` between a kill and its resume changes image IDs and ends the run.
- Test cells are small: 36-38 queries per 75-kind, 24 per 50-kind, 12-13 per runbook kind.
  #19 reports query-cluster bootstrap confidence intervals and flags cells with n < 30.
- Changing the split means a new list and a new ADR, not an edit after collection.
