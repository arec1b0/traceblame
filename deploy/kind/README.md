# Local two-tier topology in kind (#10)

Design §1.1: apps → **otel-agent** (DaemonSet, one per node) → **otel-gateway**
(Deployment, 2–4 replicas) → ClickHouse. Run everything from WSL2 (Ubuntu) in the repo root,
with Docker Desktop running.

```bash
make kind-up        # cluster `traceblame` (1 control plane + 2 workers), namespaces, Secrets
make kind-deploy    # images, ClickHouse (Altinity operator + CHI), migrations, agent, gateway
make bench-scaling  # span loss / split traces while the gateway scales 2 -> 4 -> 2
make kind-down
```

## Layout

| Path | What |
|---|---|
| `kind-config.yaml` | Cluster shape. The API server port is fixed at 16443, because Docker Desktop on WSL2 refuses some random host ports. |
| `collector/agent.yaml` | The agent: OTLP with `basicauth` (one htpasswd user per tenant), `memory_limiter`, normalizer (`tenant_source: auth`, content stage), loadbalancing exporter (`routing_key: traceID`, k8s resolver, mTLS), and a file-backed queue (512 MiB, bytes sizer). |
| `collector/gateway.yaml` | The gateway: OTLP with mTLS (agents' CA only), `memory_limiter`, a second normalizer pass (keeps the agent's tenant), `tail_sampling`, and the stock ClickHouse exporter into `otel_traces_ingest` (ADR-0004). |
| `collector/gateway-bench.yaml` | Bench-only overlay: stamps `traceblame.bench.gateway` with the pod name, so the report can tell which gateway stored a span. |
| `collector/latency-thresholds.env` | `tail_sampling` latency thresholds per service (generated by `loadgen thresholds`; source and date are in the file). |
| `manifests/` | Namespaces, the CHI, the agent DaemonSet with its EndpointSlice-only Role, and the gateway Deployment with its Services and NetworkPolicy. These are checked by kubeconform in pre-commit. |

## Decisions

- **Tenant (ADR-0005).** The agent overrides `aegis.tenant.id` with the authenticated
  htpasswd user. The gateway accepts only agents, by mTLS client certificate plus a
  NetworkPolicy, and keeps that value.
- **No NATS.** `natsexporter` v0.164.1 cannot publish to JetStream. The gateway exports to
  ClickHouse only; the trace-assembler is to poll `trace_arrivals` by arrival time instead
  (ADR-0003, Proposed; #35).
- **memory_limiter.** The cluster configs use `limit_percentage`, which works with the
  container memory limits. Local smoke tests on WSL2 merge
  `collector/test/smoke/testdata/memory-limiter-mib.yaml` over them, because the collector
  cannot read a cgroup limit there.
- **Graceful scale-down.** The gateway has `preStop` sleep 15 s, so the agents' resolvers drop
  the pod first. Then `tail_sampling` decides the pending traces (`decision_wait` 30 s) and the
  exporter flushes (10 s). `terminationGracePeriodSeconds` 75 s covers all three.
- **Credentials.** `make kind-up` generates them as Secrets and none is committed:
  - the CA and the agent and gateway certificates (valid 30 days);
  - the tenants' htpasswd and their plaintext passwords, used by the bench;
  - the ClickHouse password.

## Known limitations

- **Split traces while the gateway set changes** (design §1.1 deployment notes). After a ring
  change, a trace's later spans can go to another gateway, and each half is sampled
  independently. The bench measures how often this happens and for how long:
  `evals/reports/gateway-scaling-*.md`. Mitigation: #38.
- **Eval and injected-fault traces are not yet kept at 100%.** The profile has no attribute
  that marks them (#36, before #14).
- **The low-eval-score policy (§1.1) is not configured.** No profile attribute carries an
  eval score at ingest (#37).
- **App → agent is plain gRPC/HTTP inside the node** (ADR-0005, negative consequences).
